Migration procedure

Step-by-step: apply the NMState MachineConfigs, force-reboot each pool in order, verify.

Prerequisites

  • Maintenance window scheduled — every node reboots once; pods/VMs lose external connectivity briefly per node.
  • Console access (iDRAC/iLO) to each node available in case of a network misconfiguration.
  • oc logged in as cluster-admin: oc whoami
  • All nodes currently Ready: oc get nodes
Reboot order matters. control01 and control02 both carry the master+worker role, so a single pool reboot takes down both masters at once. etcd quorum is preserved by the arbiter (3rd member), which reboots last. The API will be briefly degraded during the master pool reboot — schedule accordingly.

Step 1 — Apply the br-ex NMState MachineConfigs

oc apply -f machineconfigs/control01-br-ex-nmstate.yaml
oc apply -f machineconfigs/control02-br-ex-nmstate.yaml
oc apply -f machineconfigs/arbiter-br-ex-nmstate.yaml

This writes /etc/nmstate/openshift/control01.yml, control02.yml, and cluster.yml to the pending config of each pool. Nothing changes on nodes until they reboot.

Step 2 — Force-reboot the master pool (control01 + control02)

force-reboot.yaml contains three documents. Split it into per-pool files, then apply only the master one:

# force-reboot-master.yaml  = document "10-force-reboot-master"
# force-reboot-arbiter.yaml  = document "10-force-reboot-arbiter"

oc apply -f force-reboot-master.yaml
watch oc get nodes   # both masters go NotReady, then back to Ready (~5-10 min)

Gate: wait until both control nodes are Ready before proceeding.

Step 3 — Force-reboot the arbiter

oc apply -f force-reboot-arbiter.yaml
watch oc get nodes   # arbiter goes NotReady, then back to Ready

Step 4 — Clean up the force-reboot MachineConfigs

oc delete machineconfig 10-force-reboot-master
oc delete machineconfig 10-force-reboot-arbiter
# (delete 10-force-reboot-worker only if you applied it; luke has no separate worker pool)

Verification

On each node, confirm NMState now owns br-ex and the config matches what was there before:

# control01 (control02 identical except IP 192.168.40.27 and file name)
oc debug node/control01.syangsao.net -- chroot host sh -c \
  "nmstatectl show br-ex | grep -v INFO; ls /etc/nmstate/openshift/"
#   br-ex (ovs-bridge) with ports bond0.40 + patch-br-ex_control01...-to-br-int
#   br-ex (ovs-interface) 192.168.40.26/24, 169.254.0.2/17, mtu 1500
#   /etc/nmstate/openshift/applied  exists

# arbiter
oc debug node/arbiter.syangsao.net -- chroot host sh -c \
  "nmstatectl show br-ex | grep -v INFO; ls /etc/nmstate/openshift/"

# Expected: ens192 -> br-ex, 192.168.40.25/24, 169.254.0.2/17

Cluster-level checks:

oc get nodes                          # all Ready
oc get pods -A | grep -v Running      # no stuck pods
ping -c 3 192.168.40.1                # external gateway reachable from a node
oc rsh $(oc get node control01.syangsao.net -o jsonpath='{.status.addresses[?(@.type=="InternalIP")].address}') \
  ping -c 3 <any-external-ip>

Confirm configure-ovs.sh now skips on every boot (it sees the applied flag):

oc debug node/control01.syangsao.net -- chroot host \
  grep -q applied /etc/nmstate/openshift/applied && echo "NMState owns br-ex"

If something goes wrong

  • Node can't reach the API after reboot: use iDRAC/iLO console. The NMState file is at /etc/nmstate/openshift/cluster.yml; you can edit it on-disk, then re-apply a corrected MachineConfig once the node is reachable. Deleting the file and rebooting restores the pre-migration state because configure-ovs.sh runs again when /etc/nmstate/openshift/applied is absent.
  • One node bad, others fine: cordon it, fix its MC (nodeSelector-style per-node MCs are not used here — the fix is a corrected pool-wide MC + targeted reboot of that node via oc debug console or by deleting its MachineConfig record and re-applying).
  • Full revert: delete both br-ex NMState MachineConfigs, delete the applied flag on each node (chroot host rm /etc/nmstate/openshift/applied), force-reboot all pools. configure-ovs.sh rebuilds the original bridge from its keyfiles.

  • Default gateway: 192.168.40.1, metric 150 (managed by OVN, not the NMState file).
  • 169.254.0.2/17 is the OVN-Kubernetes masquerade address — must be preserved.
  • bond0 on control nodes: 802.3ad, LACP slow, miimon 100, xmit_hash_policy layer2; also carries VLANs 60/80/90 (VM data) — those are not part of br-ex and are left untouched.
  • No existing OVS MachineConfig or NMState files on any node; the migration is a clean one-way switch.

The plan

  1. NMState manifests — one file per node (control01, control02, arbiter), each base64-embedded in a MachineConfig and written to /etc/nmstate/openshift/<node>.yml. Per-node IPs stay exactly as they are; nothing changes functionally.
  2. Step-by-step procedure — apply the three MCs, force-reboot each pool in order (master → arbiter), verify with nmstatectl show br-ex.
One-way door. Once the NMState file is applied, configure-ovs.sh will skip on every boot (/etc/nmstate/openshift/applied exists) and you cannot migrate back to the shell-script version. A misconfiguration can break node networking — do this in a maintenance window with console access (iDRAC/iLO) available.
IPs are immutable. Red Hat does not support changing node IPs post-installation. The migration preserves every existing address exactly as it is today.
